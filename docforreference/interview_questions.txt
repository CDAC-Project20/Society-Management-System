Project: Society Management System
Architecture: Spring Boot Microservices + React (Vite) + MySQL

--- Category 1: Project Overview & Architecture ---

1. Q: Can you explain the overall architecture of your Society Management System?
A: Sure. It's built on a microservices architecture using Java Spring Boot for the backend and React with Vite for the frontend. We have five distinct services: a Discovery Server (Eureka) for service registry, an API Gateway for central routing and CORS, an Auth Service for user management, a Society Service for core logic, and a Transaction Service for payments and documents. The frontend has role-based routing for SuperAdmin, Secretary, Owner, and Tenant.

2. Q: Why did you choose a microservices architecture over a monolithic one for this project?
A: I chose microservices because a society management system has very distinct domains. Authentication, society management, and financial transactions scale and change differently. By decoupling them, if the transaction service goes down, residents can still view notices in the society service. It also made it easier to manage role-based routing at the API gateway level.

3. Q: How do your microservices communicate with each other?
A: They communicate primarily through REST APIs. Since they are registered with the Eureka Discovery Server, they can find each other dynamically without hardcoded URLs. The API Gateway routes incoming requests from the React frontend to the appropriate microservice based on the URL prefix (e.g., /api/society/** goes to the Society service).

4. Q: What is the role of the Eureka Discovery Server in your project?
A: The Eureka Discovery Server acts as a telephone directory for the microservices. Instead of the API gateway needing to know the exact IP and port of the Auth Service, the Auth Service registers itself with Eureka. The Gateway then asks Eureka where the Auth Service is, which allows for dynamic routing and load balancing if we add multiple instances.

5. Q: What is the purpose of the API Gateway?
A: The API Gateway (running on port 8080) is the single entry point for all frontend requests. It handles global CORS configuration, routes requests to the correct backend service using `lb://` (load-balanced) URLs from Eureka, and can also be used for centralized authentication checks before requests hit the internal services.

--- Category 2: Backend Development (Spring Boot & Java) ---

6. Q: How did you implement CORS in your application?
A: Because of the microservices setup, handling CORS in every service is redundant. I implemented a global CORS configuration in the API Gateway. It allows requests from our React frontend ports (like 5173, 5174) so the browser doesn't block the API calls.

7. Q: How do you handle exceptions globally in your Spring Boot services?
A: I use `@ControllerAdvice` and `@ExceptionHandler` in Spring Boot. This allows me to catch exceptions (like UserNotFoundException or InvalidRoleException) across the whole service and return a standardized JSON response with an appropriate HTTP status code (like 404 or 403) to the frontend.

8. Q: In your Transaction Service, how are payments or documents linked to specific users?
A: Every transaction or document record in the MySQL database has a foreign key referencing the user's ID or flat ID. When an API request is made, the service validates the user's identity and role, ensuring they only see or upload documents relevant to their own flat or society.

9. Q: How did you manage database configurations for multiple microservices?
A: Each microservice (Auth, Society, Transaction) has its own `application.properties` or `application.yml` file configuring its connection to the MySQL server. They can either share a single database with different table prefixes, or ideally, have separate databases (e.g., auth_db, society_db) to enforce true microservice data isolation.

10. Q: What annotations do you use most frequently in your Spring Boot controllers?
A: I frequently use `@RestController` to define the class, `@RequestMapping` for base URLs, `@GetMapping` and `@PostMapping` for specific endpoints, and `@RequestBody` and `@PathVariable` to extract data from the incoming requests.

--- Category 3: Security & Authentication ---

11. Q: How does the login flow work in your system?
A: The user submits their email and password from React. The API Gateway routes this to the Auth Service. The Auth Service fetches the user from MySQL, verifies the password using BCrypt, and if valid, generates a JWT (JSON Web Token) or session token. The frontend stores this token and includes it in the header for future requests.

12. Q: Why did you use BCrypt for passwords?
A: BCrypt is an industry standard for password hashing. It includes a "salt" which protects against rainbow table attacks, and a work factor that slows down the hashing process, making brute-force attacks computationally expensive. It's much more secure than MD5 or SHA-256.

13. Q: How is Role-Based Access Control (RBAC) enforced in the backend?
A: We have 4 roles (SuperAdmin=1, Secretary=2, Owner=3, Tenant=4). The Auth Service assigns this role. When an endpoint is hit (e.g., adding a new notice), the Society Service checks the user's role. If a Tenant tries to post a notice meant only for Secretaries, the backend rejects it with a 403 Forbidden status.

14. Q: How do you prevent a Tenant from accessing the Secretary's dashboard?
A: Security is enforced on both sides. On the frontend, React Router checks the user's role and redirects them if they try to access an unauthorized route. On the backend, every API request is validated to ensure the requester has the correct role ID before modifying or fetching data.

15. Q: What happens if a user forgets their password? How would you implement that?
A: Currently, login is email/password based. To implement a reset, I would create an endpoint in the Auth Service that generates a secure, time-limited token, saves it to the DB, and emails a reset link to the user. When clicked, the frontend sends the new password and token back to the Auth Service to update the DB using BCrypt.

--- Category 4: Frontend Development (React & Vite) ---

16. Q: Why did you use Vite instead of Create React App?
A: Vite is significantly faster than Create React App. It uses native ES modules during development, so the server starts almost instantly, and Hot Module Replacement (HMR) is extremely quick, which speeds up frontend development tremendously.

17. Q: How do you handle routing for the 4 different roles in React?
A: I use React Router. After a successful login, the frontend receives the user's role ID (1 to 4). Based on this ID, the app dynamically renders different dashboard components (e.g., `<SuperAdminDashboard />` vs `<TenantDashboard />`) and restricts access to specific URL paths using Protected Route wrapper components.

18. Q: How do you manage global state in your React app (like user session data)?
A: I use React Context API (or Redux) to store the currently logged-in user's details and token. This makes the user data accessible to any component without having to pass props down multiple levels (prop drilling).

19. Q: How does the React app communicate with the microservices?
A: I use `fetch` or `axios` to make HTTP requests. All requests are directed to the API Gateway at `http://localhost:8080`, which then proxies them to the correct microservice. I also configure interceptors to automatically attach the authentication token to the headers of every request.

20. Q: What would happen if Server 1 and Server 2 are running simultaneously on ports 5173 and 5174?
A: Vite allows running multiple dev servers. This is useful for testing different roles simultaneously. I can log in as a Secretary on port 5173 and as a Tenant on port 5174 in different browser tabs, testing how they interact in real-time.

--- Category 5: Database & Entities ---

21. Q: Can you describe the database schema for the Society Service?
A: It involves entities like `Society`, `Flat`, `Notice`, and `Complaint`. A `Society` has a one-to-many relationship with `Flat`. A `Flat` belongs to an `Owner` or `Tenant` (linked by User ID). `Notices` are linked to the `Society`, and `Complaints` are linked to specific `Flats` and `Users`.

22. Q: How do you handle database relationships in Spring Boot?
A: I use Spring Data JPA and Hibernate. For relationships, I use annotations like `@OneToMany`, `@ManyToOne`, and `@JoinColumn`. For example, a User entity has a `@OneToMany` relationship with Complaints, meaning one user can raise multiple complaints.

23. Q: Did you face any issues with lazy loading in Hibernate?
A: Yes, sometimes when returning an entity as JSON, Hibernate tries to fetch lazy-loaded collections outside the active session, causing a `LazyInitializationException`. I solve this by using DTOs (Data Transfer Objects) to map only the needed fields before sending the response, or using `@JsonIgnore`.

24. Q: How do you ensure data consistency across microservices? (e.g., deleting a user in Auth should delete their flats in Society)
A: In a distributed system, this is tricky. The simplest way is synchronous REST calls: Auth service tells Society service to delete the flats. A more robust way for the future would be using an event broker like RabbitMQ or Kafka, where Auth publishes a "UserDeleted" event, and Society listens for it.

25. Q: What database did you use and why?
A: I used MySQL. Since the data (societies, flats, users, transactions) is highly structured and relational, a SQL database ensures ACID properties and data integrity through foreign keys, which is crucial for a financial and management system.

--- Category 6: Scenarios & Troubleshooting ---

26. Q: What happens if the Auth Service goes down?
A: Because of the microservices architecture, new users won't be able to log in or register. However, if other services are validating JWTs locally without calling the Auth service (stateless auth), currently logged-in users might still be able to use the Society and Transaction services until their token expires.

27. Q: You mentioned a `BindException` or `EADDRINUSE` in your docs. How do you resolve it?
A: This happens when a port (like 8080 for the Gateway) is already occupied by a previous crashed instance. I wrote a `stop-all.bat` script that finds and kills the Java/Node processes running on those specific ports so they can restart cleanly.

28. Q: How do you handle file uploads in the Transaction Service?
A: For document uploads, the React frontend sends a `multipart/form-data` request. The Spring Boot backend receives it as a `MultipartFile` object. It then saves the file to a local directory (or cloud storage like S3) and saves the file path/metadata in the MySQL database.

29. Q: A tenant complains they can't post a notice. How do you debug this?
A: First, I'd check the browser network tab to see the API response (likely a 403). Then I'd check the API Gateway logs to ensure the request routed correctly. Finally, I'd check the Society Service logs. The issue is likely the backend role check correctly blocking the tenant, as notices are usually for Secretaries.

30. Q: How do you test your microservices locally?
A: I use Postman to test individual backend endpoints directly (e.g., hitting port 8081 for Auth). Once the backend works, I test through the API Gateway (port 8080) to ensure routing works. Finally, I integrate it with the React frontend.

--- Category 7: Advanced / Scaling ---

31. Q: How would you scale this system if 1000 societies signed up?
A: I would deploy the microservices using Docker and Kubernetes. Eureka would handle load balancing between multiple instances of the heavy services (like Society Service). I would also move the MySQL database to a managed cloud cluster and implement caching (like Redis) for frequently accessed data like notices.

32. Q: What are the disadvantages of the microservices architecture you chose?
A: It adds complexity. Instead of one server, I have to manage five. Logging is distributed (I have 5 different log files). Data consistency is harder to maintain across databases, and local setup requires batch scripts to run multiple processes simultaneously.

33. Q: How do you track a request that passes through Gateway -> Auth -> Society?
A: Currently, I look at the individual log files in the `/logs` directory. In a production environment, I would implement Distributed Tracing using tools like Zipkin or Sleuth. It assigns a unique trace ID to the request at the Gateway, which gets passed to all downstream services, allowing me to track the entire flow.

34. Q: How do you handle pagination for notices or transactions in your React app?
A: On the backend, I use Spring Data JPA's `Pageable` interface to return chunks of data (e.g., 10 records per page). On the React side, I maintain a `currentPage` state and send it as a query parameter (e.g., `/api/society/notices?page=1&size=10`).

35. Q: What design patterns did you use in this project?
A: The architecture itself uses the **API Gateway** and **Service Registry** patterns. In the code, I used the **MVC (Model-View-Controller)** pattern, the **Repository** pattern for database access, the **DTO (Data Transfer Object)** pattern to limit exposed data, and the **Singleton** pattern managed by Spring's IoC container.

--- Category 8: Specific Feature Implementations ---

36. Q: How does the "Heartbeat monitoring" of Eureka work?
A: Each registered microservice (like Auth or Society) periodically sends a "heartbeat" ping to the Eureka server to say "I am still alive". If Eureka stops receiving heartbeats from a service for a certain time, it removes that service from its registry, and the API Gateway stops routing traffic to it.

37. Q: How is the 'Maintenance & Fee Payments' feature modeled?
A: In the Transaction Service, a `Payment` entity links a `Flat` and a `User` to an amount and date. When a payment is made, the frontend sends the details. The backend records it as "Pending" or "Completed". I would eventually integrate a payment gateway like Stripe or Razorpay to handle the actual money transfer.

38. Q: How do you ensure passwords are not accidentally logged or exposed in APIs?
A: In the User entity, I use the `@JsonIgnore` annotation on the password field so it is never serialized into JSON responses. Also, I never log the request body of the login endpoint in the Auth service logs.

39. Q: What is the purpose of the start-all.bat script?
A: It automates the local development setup. Instead of manually opening 6 terminals and setting JAVA_HOME for each microservice and the frontend, the script sets the environment, uses `start /b` to run the Spring Boot apps in the background, and outputs their logs to the `logs/` folder.

40. Q: If I want to add a "Visitor Management" feature, where would it go?
A: Because Visitor Management is a distinct domain, I could either add it as a new module within the Society Service, or if it's large enough, create a 6th microservice called "Visitor Service". I would register it with Eureka, map it in the Gateway (`/api/visitor/**`), and add a UI for the Security Guard role.

--- Category 9: React Components & Hooks ---

41. Q: Which React hooks do you use most frequently?
A: `useState` for managing local component state (like form inputs), `useEffect` for fetching data from the API when a component mounts, and `useContext` for accessing global state like the logged-in user profile.

42. Q: How do you handle form validations in React?
A: I handle basic validations (like required fields) using HTML5 attributes. For complex validation (like checking if passwords match or email format), I use controlled components with `useState` to track input changes, and validate the state before making the `POST` request.

43. Q: How do you make sure the React app is responsive for mobile devices?
A: I use CSS media queries and flexbox/CSS grid layouts. Since tenants and owners will likely use the app on their phones to check notices or pay bills, the UI components adjust their width and stacking order on smaller screens.

44. Q: What is the difference between `npm run dev` and building for production?
A: `npm run dev` starts the Vite development server with hot-reloading for local coding. For production, I would run `npm run build`, which bundles, minifies, and optimizes the React code into static HTML/CSS/JS files in a `dist` folder, which can be served by Nginx or Apache.

45. Q: Why do you have different commands like `npm run dev:superadmin` and `npm run dev:tenant`?
A: They start the Vite server on different ports (5173, 5174, etc.). This allows developers to open multiple browser windows side-by-side, logged in as different roles, to test interactions (e.g., Secretary posts a notice, Tenant sees it immediately) without having to constantly log in and out.

--- Category 10: Spring Boot Internals ---

46. Q: What is the difference between `@Component`, `@Service`, and `@Repository`?
A: `@Component` is a generic Spring bean. `@Service` is a specialization used for business logic classes. `@Repository` is used for Data Access Objects (DAOs) interacting with the DB; it also translates SQL exceptions into Spring's DataAccessException. They all register the class in the Spring Application Context.

47. Q: Explain the `@Autowired` annotation.
A: It is used for Dependency Injection. If my `SocietyController` needs the `SocietyService`, I use `@Autowired` (or constructor injection). Spring automatically provides an instance of the service when it creates the controller, so I don't have to manually use the `new` keyword.

48. Q: How do you map a DTO to an Entity in Spring Boot?
A: I can do it manually by creating a helper method that copies fields from the DTO to the Entity using getters and setters. For larger projects, I use libraries like MapStruct or ModelMapper to automate the mapping based on field names.

49. Q: What is application.properties used for?
A: It holds configuration properties for the Spring Boot app. In this project, it configures the server port, MySQL database URL, username, password, JPA/Hibernate settings (like `update` or `create-drop`), and Eureka client settings.

50. Q: What happens when you put `spring.jpa.hibernate.ddl-auto=update`?
A: When the application starts, Hibernate checks the database schema. If tables or columns are missing based on the Entity classes, it automatically generates and executes the SQL to alter or create them, which is very helpful during development.
